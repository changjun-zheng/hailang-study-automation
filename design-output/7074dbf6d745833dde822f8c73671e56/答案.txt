（1）参与对象的确定

把用例的分析类模型按「边界—控制—实体」三层摊开得到顺序图的对象：边界对象 :借阅界面 / :注册界面（读者唯一入口），控制对象 :借阅控制器 / :用户控制器（一个用例一个控制器，只编排不碰库），实体服务 :图书服务、:借阅记录服务 / :校验服务、:用户服务（对应题干里的图书资源、借阅记录、用户信息三类数据），存储 :数据库（带 <<database>> 构造型），另外各画一个临时对象 :借书事务 / :注册表单DTO 来体现对象生命周期。:读者 作为外部 Actor 画在最左侧。

（2）图书借阅顺序图

消息序列：1 读者 → :借阅界面 inputInfo(isbn, cardNo)；2 :借阅界面 → :借阅控制器 borrow(isbn, cardNo)；3 :借阅控制器 → :图书服务 getBook(isbn)；4 :图书服务 → :数据库 SELECT t_book；5 返回 Book；6 返回库存与状态；随后进入 alt 组合分片——第一操作数 [不可借：库存为 0 或状态不允许] 走 7a 返回不可借；第二操作数 [可借：新建事务、写记录、扣库存] 走 7b <<create>> 新建 :借书事务、8 createLoan(r, b)、9 INSERT t_loan、10 返回 loanId、11 decreaseStock(bookId)、12 commit() 并 <<destroy>> 销毁事务；分片之外 13 :借阅控制器 → :借阅界面 借阅成功(应还日期)、14 :借阅界面 → 读者 显示借阅凭证。图见附件 顺序图_图书借阅.png。

（3）用户注册顺序图

消息序列：1 读者 → :注册界面 inputInfo(user)；2 :注册界面 → :注册表单DTO <<create>> 封装表单；3 :注册界面 → :用户控制器 register(user)；4 :用户控制器 → :校验服务 validate(user)；5 :校验服务 → :数据库 SELECT byName；6 返回匹配结果；alt 分片第一操作数 [重名或格式非法：直接返回失败] 走 7a 校验不通过，第二操作数 [校验通过：加密后落库] 走 7b 校验通过、8 save(user)、9 INSERT t_user、10 返回 userId、11 注册成功、12 :注册表单DTO <<destroy>> 销毁表单；分片之外 13 注册结果回界面、14 提示注册完成。图见附件 顺序图_用户注册.png。

（4）设计取舍与评分点对照

密码加密不单独画成消息，它是 :用户服务 的内部行为，顺序图只表达对象间可见交互；第 13、14 条返回画在分片之外，因为不论走哪个操作数控制器都要把结果回给界面，塞进分片会重复两遍。对照评分标准：对象正确性——对象全部由题干 8 个功能反推；交互正确性——界面不直连数据库，一律经控制器调度；消息顺序——编号 1→14 即时间顺序，调用实线、返回虚线，可借/不可借用 alt 显式分叉；对象生命周期——:借书事务 与 :注册表单DTO 都不在顶部出现，而是在被创建那一行以对象框出现，销毁处画 X；清晰度——对象统一置顶、生命线等距、每条消息带编号与参数、守卫条件写在分片左上角。
